# Выделенный сервер LessonGame

Как поднять сервер, за которым никто не играет: игроки подключаются к нему как клиенты,
место «хозяина» не занято (входят все 20), а матч стартует сам, когда набралось нужное
число игроков. Отдельной «серверной» сборки не требуется — режим включается аргументом.

План и история решений — [`multiplayer_plan.md`](multiplayer_plan.md) (этапы M6.1–M6.4).

## Коротко

```powershell
# из редактора движка (так проверено; под песочницей DSH нужен ещё редирект APPDATA)
& 'C:\Program Files\Godot_v4.6-stable_win64.exe\Godot_v4.6-stable_win64_console.exe' `
    --headless --path . -- --server --min-players=2 --admin-token=СЕКРЕТ --name=MyServer

# из собранной игры
LessonGame.console.exe --headless -- --server --min-players=2 --admin-token=СЕКРЕТ
```

Всё, что **после `--`**, — аргументы проекта; до `--` — движка (`--headless` обязателен,
иначе сервер попытается открыть окно).

## Аргументы

| Аргумент | Что делает |
|---|---|
| `--server` | включает режим выделенного сервера |
| `--config=путь` | откуда читать настройки (по умолчанию `server.cfg` рядом с игрой) |
| `--min-players=N` | сколько игроков ждать до автостарта матча (по умолчанию 1) |
| `--port=N` | игровой порт UDP (по умолчанию 8910) |
| `--max-players=N` | предел участников, не больше 20 |
| `--password=P` | пароль на вход; пусто — вход свободный |
| `--admin-token=P` | включает админ-команды; пусто — команды выключены |
| `--name=…` | имя сервера в списке найденных игр в локальной сети |
| `--dtls` | шифрование канала; **нужно и клиентам** (см. «Оговорки») |

**Аргументы перекрывают файл настроек** — удобно для разового прогона, не правя `server.cfg`.

## Файл настроек `server.cfg`

Рядом с игрой (при запуске из редактора — в корне проекта) лежит `server.cfg`. В собранной
игре он уже лежит в архиве; если файла почему-то нет, сервер создаёт его при первом запуске
вместе с подсказками в комментариях: строки начинаются с `;`, значения — как в INI.

Читать файл не обязательно: у каждой строки есть комментарий, а тот же шаблон печатает сам
сервер при первом запуске. Настройки дублируются аргументами командной строки (см. выше),
поэтому для разового прогона конфиг можно не трогать.

```ini
[server]
; как сервер виден в списке игр локальной сети
name="Выделенный сервер"

; игровой порт UDP; клиенты указывают адрес как host:port
port=8910

; пусто — вход свободный
password=""

; пусто — админ-команды выключены
admin_token=""

; сколько игроков ждать до автостарта матча
min_players=1

; предел участников, не больше 20 (сервер не занимает место среди игроков)
max_players=20

; шифрование канала; клиенты при этом должны запускаться с --dtls
dtls=false
```

Путь можно задать явно: `--server --config=D:\servers\my.cfg` — так удобно держать несколько
серверов рядом.

**При обновлении версии** сборка распаковывается в новую папку, и `server.cfg` в ней — снова
шаблон: свои настройки нужно перенести руками (или сразу держать конфиг вне папки игры и
указывать его через `--config=`, тогда при обновлении ничего не теряется).

## Запуск ярлыком (двойным кликом)

В репозитории есть два лаунчера в `tools/server/`:

| Файл | Для чего |
|---|---|
| `run_server.bat` | для собранной игры: положить рядом с `LessonGame.console.exe` и запускать двойным кликом |
| `run_server_dev.bat` | для запуска из исходников: поднимает сервер редакторским бинарником движка |

Оба открывают консольное окно, подтягивают `server.cfg`, печатают лог и **не закрываются
после остановки** (в конце `pause`), чтобы сообщение об ошибке можно было прочитать.

Как сделать ярлык на рабочем столе: правый клик по `.bat` → «Отправить» → «Рабочий стол
(создать ярлык)». Иконку можно поменять в свойствах ярлыка, указав `LessonGame.exe` из
папки сборки.

В собранной игре лаунчер и конфиг уже есть: скрипт сборки (`lesson-game-build`) кладёт в
папку версии `run_server.bat` и шаблон `server.cfg`, и оба попадают в архив. Порядок такой:
распаковать сборку, открыть `server.cfg` (внутри подсказки по каждой строке), поправить,
запустить `run_server.bat` двойным кликом.

### Шифрование (DTLS) в лобби

В лобби есть галочка **«Шифровать канал»** — она работает и у хоста (поднимает сервер с
шифрованием), и у клиента (подключается к шифрованному). В списке найденных игр
шифрованные помечены `(DTLS)`, и при клике по такой записи галочка включается сама.
Флаг `--dtls` делает то же самое для запуска из командной строки.

## Порты и файрвол

| Порт | Зачем |
|---|---|
| **UDP 8910** | игра; это порт по умолчанию, свой задаётся в `server.cfg` (`port=`) или аргументом `--port=` |
| UDP 8911 | поиск серверов в локальной сети; нужен, только если сервер должен находиться в LAN |

Игроки в интернете подключаются по адресу и порту: в поле адреса можно писать
`192.168.0.10` (порт 8910) или `192.168.0.10:9000`, если у сервера свой порт. Список
найденных игр работает только внутри одной локальной сети и подставляет адрес вместе с
портом сам.

Правило файрвола — **по портам, а не по exe**: правило по пути ломается на каждой новой
сборке (подробности — в скилле `lesson-game-build`).

```powershell
# разрешить (от администратора)
New-NetFirewallRule -DisplayName "LessonGame UDP 8910-8911" -Direction Inbound -Protocol UDP -LocalPort 8910,8911 -Action Allow -Profile Any

# убрать
Remove-NetFirewallRule -DisplayName "LessonGame UDP 8910-8911"
```

## Что должно быть в логе

```
SERVER LOCAL ADDRESSES: 192.168.100.2, 25.11.113.123
SERVER READY: порт 8910, игроков до 20, автостарт от 2, админ-команды включены, DTLS выключен
SERVER: + Вася (peer 123456789), участников 1
GAME STARTED: участников 2
SERVER: - peer 123456789, участников 1
```

Адреса сервер печатает все: у машины с Hamachi, Hyper-V и VPN их несколько, и рабочий —
тот, который видит вторая сторона. Если в интернете не подключается, а локально всё
работает, дело почти всегда в файрволе или в выборе адреса.

## Как подключаются игроки

Меню → «Мультиплеер» → адрес машины сервера → «Присоединиться». Пароль вводится там же,
если сервер запущен с `--password`. Сервер не занимает место среди игроков, поэтому
подключиться могут все 20.

## Админ-команды

Отдельного консольного клиента нет: команду отправляет любой клиент, который знает токен
и подключился к серверу, — `NetworkManager.send_admin_command(token, команда, аргумент)`.

| Команда | Аргумент | Что делает |
|---|---|---|
| `kick` | ник игрока | отключает игрока; он видит причину в лобби |
| `stop` | — | гасит матч и завершает процесс сервера |
| `status` | — | печатает список участников в лог сервера |

В смоуке для этого есть готовые флаги (удобно, если своего клиента-утилиты ещё нет):

```powershell
& $godot --headless --path . res://core/dev_checks/network_smoke.tscn -- --autoconnect=127.0.0.1 --name=Admin --admin-token=СЕКРЕТ --admin-kick=Вася
& $godot --headless --path . res://core/dev_checks/network_smoke.tscn -- --autoconnect=127.0.0.1 --name=Admin --admin-token=СЕКРЕТ --admin-stop
& $godot --headless --path . res://core/dev_checks/network_smoke.tscn -- --autoconnect=127.0.0.1 --name=Admin --admin-token=СЕКРЕТ --admin-status
```

С неверным токеном команда отклоняется и попадает в лог сервера (`ADMIN: команда «…»
отклонена — неверный токен`).

## Остановка

`Ctrl+C` в консоли сервера либо `Stop-Process` по его процессу. Аккуратно, с сообщением
клиентам и записью в лог (`SERVER STOPPED`), — админ-команда `stop`.

## Развёртывание

**systemd (Linux).**

```ini
[Unit]
Description=LessonGame dedicated server
After=network-online.target

[Service]
WorkingDirectory=/opt/lessongame
ExecStart=/opt/lessongame/LessonGame.x86_64 --headless -- --server --min-players=2 --admin-token=SECRET --name=MyServer
Restart=on-failure
User=lessongame

[Install]
WantedBy=multi-user.target
```

**docker.**

```dockerfile
FROM ubuntu:24.04
WORKDIR /srv
COPY LessonGame.x86_64 LessonGame.pck ./
EXPOSE 8910/udp 8911/udp
ENTRYPOINT ["./LessonGame.x86_64", "--headless", "--", "--server", "--min-players=2"]
```

```bash
docker run -d --name lesson-game -p 8910:8910/udp -p 8911:8911/udp lesson-game
```

**Linux-сборка** — отдельный шаг: шаблонов экспорта под Linux на машине сборки нет (skill
`lesson-game-build` копирует только windows). Логика сервера от платформы не зависит —
режим определяется аргументом `--server`, а не тегом сборки, — поэтому проверенное на
Windows переносится на Linux без правок кода.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `Не удалось создать игру на порту 8910` | порт занят другим хостом или прежним сервером; найти и остановить |
| Клиент не подключается снаружи, локально всё работает | входящий UDP режется файрволом: правило по портам выше |
| В логе сервера `mbedtls error: returned -0x7700` и `ERROR: TLS handshake error: -30464` | к DTLS-серверу постучался клиент без `--dtls`; рукопожатие отклонено — это ожидаемо, а не сбой игры |
| Лобби долго показывает «Подключение к …» | ENet замечает недостижимый адрес примерно через 30 с; дождитесь текста про адрес и файрвол |
| Игра видна в списке дважды | у хоста несколько интерфейсов (Ethernet, Hamachi, Hyper-V); попробуйте второй адрес или введите адрес вручную |
| Игрок подключился, но стоит на месте | он ещё не вошёл в мир (загружает карту); движение уходит только вошедшим |
| Матч не начинается | не набралось `--min-players` игроков |

## Оговорки

- **`--dtls` включает шифрование, и его нужно включать с обеих сторон.** В лобби для этого есть галочка «Шифровать канал», в командной строке — флаг; в списке найденных игр шифрованные помечены `(DTLS)`, а клик по такой записи включает галочку сам. Хост и клиент должны сойтись: если хост шифрует, а клиент нет, подключения не будет (в логе сервера при этом будут ошибки рукопожатия mbedTLS).
- **Сертификат самоподписанный и создаётся при каждом запуске**, клиент его не проверяет
  (`TLSOptions.client_unsafe`): канал шифруется, но подмена сервера не отсекается.
- **Проверено на редакторском бинарнике движка.** Собранная игра должна работать так же,
  потому что режим включается аргументом, но сборки, существовавшие до появления
  `--server`, сервером не запускались.
- **Лимиты канала:** 2 канала ENet на пира, по 32 КБ/с в каждую сторону и пределы размеров
  пакетов (64 КБ синхронизация, 4 КБ дельта). Ввод движения идёт каждый тик — около
  1,2 КБ/с с клиента.
- **Состояние мира живёт в памяти** и теряется при остановке сервера (кто что сломал и
  подобрал — сбрасывается).
